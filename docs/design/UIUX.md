# Tripwise UI/UX

| 项 | 当前决定 |
|---|---|
| 主布局 | 左侧旅行栏、中央对话、右侧网页/来源；行程与准备清单使用独立视图。 |
| 图标 | 全站 Lucide；图标用于识别和压缩操作，不单独承担关键含义。 |
| 设计原则 | 少写解释性文字，让分组、顺序、留白和图标表达层级。影响选择、隐私或可信度的信息仍要就近说明。 |
| 依据 | [PRD](../PRD.md) 定义行为与验收；[项目进度](../PROJECT-STATUS.md)记录实现和验证状态；[竞品与渠道调研](../research/scraping-references.md)记录外部证据。 |

## 1. 设计原则

- **先看结构。** 每个视图突出一个主任务；用标题、分组、对齐和间距表达关系，不用重复副标题解释布局。
- **文字从简。** 按钮写动作，状态写结果和下一步。避免营销话、模型自述、重复说明和无决策价值的标签。
- **图标有边界。** 导航图标配短标签；图标按钮提供可访问名称。来源、估算、错误和不确定性同时用文字表达，不能只靠颜色或图标。
- **详情按需展开。** 高频操作和当前结果直接可见；来源、预算、历史字段和低频设置按需查看。
- **关键信息就近。** 删除范围、密钥去向、未保存状态、事实来源和风险提示放在相关操作旁。保留具体边界，不用统一免责声明代替逐项状态。
- **单一事实来源。** 每轮只展示一份可审阅计划；修订差异紧跟摘要，详细内容按天展开。草案确认后才成为新版本。

## 2. 工作区

```text
┌────────────────┬──────────────────────────────┬────────────────────┐
│ 旅行与话题      │ 当前旅行                     │ 网页 / 来源         │
│                │                              │                    │
│ 新建旅行        │ 规划 · 行程 · 出行准备       │ 当前网页或资料卡    │
│ 旅行列表        │ 对话、进度、计划与修改       │ 来源、时间与状态    │
│ 话题列表        │                              │                    │
│ 设置与备份      │ 输入下一条需求或修改意见     │ 可收起、可调整宽度  │
└────────────────┴──────────────────────────────┴────────────────────┘
```

| 区域 | 呈现方式 |
|---|---|
| 左侧旅行栏 | 品牌、旅行列表和当前旅行话题；底部放备份与设置。折叠后保留展开入口。删除操作说明影响范围。 |
| 中央工作区 | 顶部显示当前旅行及少量全局动作；「规划 / 行程 / 出行准备」切换主视图。聊天输入始终承接补充和修改。 |
| 右侧面板 | 在隔离网页和来源列表间切换。浏览器自动化时保持可见，显示同一页面、当前动作和网页内目标指示。 |

### 规划

对话承载需求补充、研究进度和计划修订。首轮欢迎页用短示例帮助开始，不强迫填写完整表单。进度区显示真实运行状态、耗时和最近工具结果；「全部步骤」按需展开工具调用序列，逐项标明执行中、完成、部分完成或失败，并显示工具回传的 `error`、`warning` 或 `info`。Agent 工具循环是动态的，不展示猜测阶段或虚构百分比。错误意味着候选未保存；警告允许 Agent 继续核验，也允许用户审阅当前计划。结束后显示明确结果并保留本轮工具记录；下一轮开始时更新。进度只来自实际 Agent 事件，不展示模型内部推理、敏感参数或凭空生成的步骤。

计划卡先显示摘要和修订差异，再按天展示地点、时间、用餐与接驳。来源、预算、时间检查和辅助说明按需展开；会阻止确认的冲突直接展开。字段级入口放在对应日期、地点或时段旁，点击后只预填修改意见，不自动发送。具体规则见 [PRD-07](../PRD.md)。

### 行程

地图和时间线共用当前版本与选中日期/地点。地图表达位置和路线服务结果；时间线表达顺序、时段和编辑。未定位地点保留在列表中。路线耗时、来源和查询时间就近显示；估算或冲突不通过颜色单独表达。编辑先形成草稿，检查差异后保存为新版本。

### 出行准备

清单按适用日期、截止日和未指定日期分组；完成状态用复选框表达。准备入口使用“图标 + 短标题”，不附重复说明；完整要求放入可编辑的对话草稿。来源状态和地点关系显示在对应事项旁。

### 网页与来源

来源卡按“类型/性质、标题、摘要、时效或状态、来源与操作”组织。搜索摘要、页面声明、图像线索和动态事实区分呈现；信息冲突、过期或未核验时在对应事实旁说明。无资料时提供搜索和粘贴入口，不显示泛化免责声明。

浏览器自动化在右侧同一页面中进行。网页内光标和目标高亮展示定位、移动、点击与滚动；用户可停止并接管。登录、验证或读取失败时显示状态和可继续动作。权限与数据边界见 [PRD-02](../PRD.md)、[浏览器控制 ADR](adr/0016-visible-research-browser-control.md) 和 [Computer Use ADR](adr/0019-browser-scoped-computer-use.md)。

### 设置

默认打开模型页，只放模型来源、凭证状态和必要操作。已保存密钥保持遮蔽；接口地址和模型名按需展开。信息源页把低频开关收在折叠组中，摘要显示启用数量；展开后只列名称、服务商和最近状态。详细数据去向集中在隐私说明，避免重复文案。

## 3. 文案与视觉

| 场景 | 规则 |
|---|---|
| 按钮 | 使用具体动作，如「继续修改」「保存为新版本」「查看来源」。图标按钮提供可访问名称。 |
| 状态 | 先说发生了什么，再给可执行下一步；成功态不重复描述页面已有内容。 |
| 表单 | 字段名表达含义，占位符只给短示例；不加通用副标题。 |
| 空状态 | 一句说明当前位置，加一个开始动作；不重复导航或页签标题。 |
| 来源/估算 | 在事实旁显示来源、时间和核验状态；来源关联不等于事实已独立核实。 |
| 删除/隐私 | 说明删除范围、备份内容或数据去向；用短句保留实际边界。 |

用中性色建立层级，以旅行绿突出主要操作和当前选择；警告色只用于真实问题。卡片靠对齐和留白区分，不额外叠加标签。图标统一用 Lucide；品牌标记单独绘制。

### 设计参考与评审

[Impeccable 4.8.2](https://github.com/pbakaus/impeccable/tree/f2baa414a87d9acf1e21ccf776bfaec0262ad6df) 是开源的 Agent 设计技能，不是行业标准。Tripwise 借鉴它的问题诊断、技术审查和去冗余方法，不套用其视觉主题。

上游 `distill` 的取舍：沿用熟悉的桌面控件，删除重复说明和无效容器，低频设置渐进展开；保留核对计划必需的来源、不确定性和工具记录。Tripwise 右侧网页/来源面板直接服务于研究和监视，不套用通用“移除侧栏”建议。Agent 进度显示真实状态、耗时、工具结果和可展开步骤，不显示推断阶段或模型思维链。

Impeccable 是设计评审技能，不是无障碍或视觉规范。当前技能将 Tripwise 归为 Operate 界面：扫描速度、一致性、原生桌面习惯和真实任务优先于装饰。先选具体问题和单个工作流，保留已建立的布局、内容与行为；只修复确认的问题，再看实际渲染结果。源代码扫描检查实现规则，URL/CDP 扫描检查渲染页面；干净扫描不等于完整 UX 验收。[改进现有界面](https://impeccable.style/docs/improve-design/)；[设计系统用法](https://impeccable.style/docs/design-system/)；[检测器扫描](https://impeccable.style/docs/detector/)。

这套方法落在 Tripwise 的下一轮：只评审“运行中的 Agent → 计划草稿 → 来源核对”一条链路。用真实长任务检查当前动作、最近工具结果、可审阅计划和来源状态是否一眼可辨；已完成的工具细节可收起，警告/错误和影响计划的待核验事实保持就近可见。重点是长任务中断后用户能判断进度、结果和下一步，不重做三栏工作区，也不叠加解释性标签。截图夹具和代码扫描不足以替代真实旅行数据下的可视复核。

不安装 Impeccable 自动 hook 或 Live Apply。上游说明 Live Apply 在聊天 Agent 一分钟未轮询时可能启动本机 Codex CLI，并使用跳过审批和沙箱的参数；本项目只借鉴人工审查方法。4.8.2 支持通过本机 CDP 扫描运行中的 Electron 窗口；若用于验收，只给临时测试进程开放 loopback 调试端口，不加入产品默认启动参数。沿用现有 PRD 和 UIUX，不生成重复的 `PRODUCT.md` / `DESIGN.md`。

主审查流程：新建旅行 → 查看真实工具步骤和结果 → 检查来源 → 修改某天或地点 → 比较并保存新版本。保留用户决策需要的交通、时段、来源和不确定性；状态文案说明结果和下一步，不显示模型内部推理。

## 4. 状态与恢复

| 状态 | 主要反馈 |
|---|---|
| 无旅行/无计划 | 示例输入或创建入口；不要求先配置全部工具。 |
| 正在规划 | 当前真实状态、耗时和工具结果；完整步骤可展开；可停止，已完成来源保留。 |
| 本轮已结束 | 显示成功或失败状态与完整工具步骤；新一轮开始后替换本次记录。 |
| 部分来源失败 | 只在失败来源旁显示原因；可单项重试、跳过或继续查看成功结果。 |
| 事实待核验或冲突 | 在相关地点/时段显示来源和状态；不把估算写成确定事实。 |
| 计划待审阅 | 显示差异与未解决项；未确认内容不覆盖已保存版本。 |
| 浏览器需接管 | 保留当前页面，显示登录/验证或读取状态；用户处理后可继续读取。 |
| 删除与连接移除 | 确认前列出实际影响范围；运行中的任务完成或停止后才能删除。 |

## 5. 可访问性

- 核心流程支持键盘；焦点顺序与三栏阅读顺序一致。弹窗管理焦点，关闭后回到触发控件。
- 设置页签仅当前项进入 Tab 顺序；左右方向键切换，Home/End 跳至首尾。
- 交互控件有明确名称和焦点样式；颜色不是唯一状态编码。遵守系统减少动态效果设置。
- 界面缩放范围为 50%–200%；侧栏与右侧面板可收起，内容区不横向溢出。
- 自动化与对比度检查、人工平台验收和屏幕阅读器结果分开记录。最新证据与未完成项见[项目进度](../PROJECT-STATUS.md)。

## 携程功能参考与本项目取舍

携程中国版[AI 行程助手](https://www.ctrip.com/tripplanner/)公开介绍路线核验、游玩时长、交通估算和地图编辑；Trip.com 海外版[Trip.Planner 发布说明](https://www.trip.com/newsroom/trip-com-launches-trip-planner-smart-itineraries-tailored-to-your-travel-style-with-real-time-recommendations/)列出活动排序、替换、删除、备注和 AI 建议。公开资料不能证明实机体验，也不代表中国版规格。

Tripwise 采用按日时间线、差异预览、对象旁的细粒度修改入口和对话式 AI 协作；列表拖排由 Agent 复核后生成新草案。地图直接改计划暂缓，直到地点定位、时间与路线能在一次修改后可靠复核。采用这些模式是为了让用户看清修改范围和结果，不声称像素级复刻竞品。
