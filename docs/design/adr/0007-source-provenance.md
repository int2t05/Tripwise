# ADR-0007：来源性质标签与页面自报元数据

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（2026-10-17）；来源内容等级补充（2026-10-24） |
| 背景 | PR-03/04 需要让用户判断来源性质和时效；地点关联来源无法说明具体开放时间、价格或预约事实由哪条材料支持，通用搜索、用户导入和 MCP 结果的元数据也不完整。 |
| 决策 | 保存有限的渠道性质标签和页面自报元数据；行程中的具体时效事实单独记录并各自绑定一条成功来源，冲突值并列展示。 |

## 背景

网页搜索、地图/天气服务、用户主动导入和 MCP 插件提供的证据形式不同。搜索摘要常不带作者或发布日期；政府域名也不能证明页面中的具体价格、开放时间仍有效；小红书等社区域名不能证明发布者是游客。若直接让模型将这些来源分为“官方”或“游客经验”，会把推断伪装成事实。

## 决策

- `SourceRecord.sourceNature` 表示 `service`、`government-domain`、`community-platform`、`user-provided` 或 `unclassified`。它描述数据工具类型或明确匹配的域名，不表示来源可信度、内容真实性或信息仍然有效。
- `SourceRecord.contentLevel` 表示本地保存的是 `snippet`、`page`、`structured`、`user-provided`、`plugin` 或 `status`。搜索摘要可以发现原文，但不能单独为开放、票价、预约或闭馆声明提供 `sourced` 依据；天气和交通还必须匹配相应的结构化来源类型。来源等级与来源性质分开：正文内容等级不代表页面可信或事实正确。
- 社区平台列表采用精确域名或子域名后缀匹配。未知域名保留 `unclassified`；近似后缀不得命中。
- `declaredAuthor` 和 `declaredPublishedAt` 只保存用户主动导入页面的有限、清理后元数据；来源卡使用“页面声明，未独立核验”标签。模型也必须沿用这个不确定性。
- 候选行程的每个地点可关联最多 6 个当前旅行来源；每个事实声明单独记录类型、值、适用范围、证据状态和最多一个来源 ID。`sourced` 声明必须引用当前旅行中成功且内容等级与事实类型匹配的来源；模型可见本轮工具来源的 ID、标题、链接、获取时间和限长摘要。主进程在候选保存时校验来源归属、成功状态和内容等级；这项检查不替代对原文语义的人工审阅。
- 条件备选是挂在原停靠点上的独立条目，分别保存候选地点、片区、触发条件和独立来源 ID；不加入正式时间线，也不得同时作为正式行程中的地点。用户明确要求预约失败替换时，缺少具体结构会拒绝候选并给有限修订机会；来源缺失只将备选标为 `pending`，不阻断其他完整行程。只有成功来源的标题、摘要或结构化地图地点直接提及候选名称时才标为 `sourced`。用户移除来源时同步解除备选来源并降级状态。
- 用户要求逐日天气时，执行端按行程日期从成功/部分覆盖的结构化天气记录中提取精确日期行；没有匹配的预报就保存 `unknown`，不让模型从摘要或常识补天气。日状态与来源跟随行程版本、备份和 Markdown 导出；删除天气来源时降为未知，手动改变日期时清除旧天气。
- 用户明确要求每天给室内雨天替代时，每个有游览活动的日期必须包含具备地点、片区、降雨触发、`environment=indoor` 和直接地点来源的条件项；缺项触发有界模型修正，不能把替代点排进正式行程。片区与室内属性是资料支持下供用户审阅的建议，不代表系统已测量到访距离或独立确认室内属性。
- 地点级来源仍只表示地点建议的相关资料。相同事实类型与范围下，不同成功来源给出不同值时并列保留，界面标“信息冲突 · 请核对”，导出包含每条值和来源元数据；应用不自动判断哪个来源正确。
- 修改地点、时段、说明或所属日期会清除该地点的地点级来源和事实声明并重置为 `pending`；纯显示/布局编辑不改变证据。来源性质、自报元数据、内容等级、地点证据和 `factClaims` 都是可选字段；旧数据无需迁移，旧来源按已知工具类型保守推断内容等级，无法推断时按搜索摘要处理。
- 网页正文、MCP 工具说明、链接和页面自报元数据均是不可信输入。不得把它们当作系统指令或认证证明。

## 后果

来源性质与内容形式更清晰，Agent 可以区分“发现链接”和“读取页面”；作者/发布日期可见时不再随手动导入丢失；候选和已确认行程可以追溯地点及事实级来源。内容等级检查仍不能证明页面当前有效，也不能语义验证网页摘录；域名分类不识别所有官方机构、不验证域名所有权，也不解决同一来源内部的观点冲突。PR-04 仍需经过审查的 UGC 连接器、作者/日期规范化和真实用户可用性评估。

## 未选择的方案

- **由模型猜来源类型：** 不采纳。搜索片段和页面措辞会诱发错误归类，且输出难以稳定复核。
- **把所有政府网页标成已核实官方事实：** 不采纳。域名只说明网站域名类别，不证明内容当前有效或适用于本次旅行。
- **把所有社区域名标成游客亲历：** 不采纳。社区平台可能包含商户、机构或转载内容；作者身份仍需来源本身提供证据。
- **没有作者/时间字段时省略来源内容：** 不采纳。保留链接、渠道标签、抓取时间并标为待核，比隐藏可用资料更有帮助。
