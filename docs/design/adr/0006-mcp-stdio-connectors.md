# ADR-0006：本机与远程 MCP 信息源接入

| 项 | 内容 |
|---|---|
| 状态 | stdio、Streamable HTTP 新旧协议协商及旧式 SSE 已实现；真实服务联测和人工安全审阅待完成。 |
| 日期 | 2026-10-17 |
| 关联 | [PRD](../../PRD.md)、[TECH](../TECH.md)、[UI/UX](../UIUX.md)、[工具边界](0002-tool-connectors.md) |

## 背景

用户将出行信息渠道覆盖和工具开发作为产品重点，希望复用地图、天气、网页和社区攻略等多种工具。桌面端需要兼容用户安装的 stdio MCP 和供应商远程 MCP。stdio 服务由 Tripwise 启动并以当前用户权限运行；远程服务会收到用户授权的工具参数和旅行查询，需要 HTTPS、凭证隔离、目标主机限制和清楚的数据流说明。内置旅行连接器仍须在插件不可用时继续工作。

## 决策

1. 支持用户手动配置的 stdio、远程 Streamable HTTP 和兼容旧服务的 SSE transport；远程地址只允许 HTTPS（回环测试地址可用 HTTP），不支持公共插件市场、自动搜索安装或自动运行。高德预设固定使用官方 Streamable HTTP 地址。
2. 使用官方 `@modelcontextprotocol/client` TypeScript SDK。stdio 与 Streamable HTTP 自动探测 MCP `2026-07-28` 无状态协议；仅在收到明确的新协议能力声明时使用新协议，否则回退到 `initialize` 握手，兼容 `2025-11-25` 及更早服务。旧式 SSE 固定使用握手协议，因为它是迁移兼容传输。每轮对话按设置连接启用的服务、发现工具，结束、取消或失败后关闭客户端与 stdio 子进程；远程连接也受连接和调用时限约束。
3. 设置页提供服务名称、传输类型、命令/参数或远程地址、认证引用、服务启用开关和已批准工具名。命令不经过 shell；命令、参数、远程地址和凭证引用保存在普通本地设置文件，环境密钥只交给主进程凭证库。远程认证头名称不得覆盖 HTTP framing、内容协商或 MCP 版本/工具路由参数头。高德服务直接引用已保存的高德 Web 服务 Key，不在 MCP URL 或设置文件中保存 Key。
4. 用户先主动点击「测试连接并发现工具」。应用临时连接并发现工具，最多等待 12 秒，随后关闭连接；草稿配置和新输入密钥不写入设置/凭证库。编辑已有服务时，未重新输入的已保存密钥只供该次预检使用。用户审阅工具后另行保存服务及逐项授权。只有 MCP 注释含 `readOnlyHint=true` 且不含 `destructiveHint=true` 的工具可被勾选；高德远程服务额外屏蔽个人地图生成、导航、打车、订票和下单类命名工具，即使服务错误地标为只读也不可调用。注释来自外部服务，不能证明代码真的只读；UI 提示用户仅连接可信服务。
5. 最多保存 8 个服务；每轮最多向模型提供 24 项已批准工具。连接/发现超时 12 秒，工具调用超时 45 秒，MCP JSON-RPC 缓冲区 1 MB，工具 schema 12 KB，返回内容交给模型前最多 12 KB。超限工具不提供给模型。
6. 只给 MCP 工具传入本轮模型生成的工具参数，不传整个 Trip JSON。结果和工具元数据一律作为不可信输入；忽略图片/二进制块；资源链接只接受普通 HTTP(S)，拒绝 URL 凭证和敏感查询参数，并去除片段标识。进入模型或来源卡的工具文本、链接标题/说明、结构化结果回退文本及工具描述也会清理敏感访问 URL、移除片段；含敏感 URL 的工具参数 schema 不会提供给模型。来源卡保存提供方、时间、限长摘要和可选链接。已配置凭证直接回显会做文本脱敏，但无法防止编码、拆分或语义转换后的泄露。
7. stdio 服务可读取它获准使用的环境密钥，并拥有当前操作系统用户的文件和网络权限。远程服务会收到本轮发给它的旅行查询参数和配置的认证信息；网络请求限制在配置主机并拒绝跨主机跳转。Tripwise 不提供 OS 级本机插件沙箱，也不审计远程服务实现；连接服务不代表 Tripwise 背书其数据质量、隐私政策或来源许可。
8. MCP 环境密钥与模型、高德密钥一样保存在独立的本机凭证 JSON，存储规则见 [ADR-0013](0013-local-json-credentials.md)。删除服务时先清除对应密钥，再移除连接配置。
9. MCP 连接失败或某工具调用失败不阻塞内置来源；连接/协议能力发现失败和工具调用失败都作为脱敏插件来源展示，不自动重试。用户可从来源卡重试单个连接检查或同一个已批准的只读工具；执行前重新检查服务启用状态、工具授权和只读标记，重试描述必须属于 connectorId 匹配的插件来源。仅当工具参数通过有界 JSON 校验且不含已配置凭证、凭证字段或常见明文凭证格式时，才把必要参数保存为来源重试描述；不符合条件时明确提示用户需在新一轮对话重新发起。调用参数不写入日志或服务 stderr。设置页只展示所选旅行最近一次运行结果，未运行不代表健康。

## 后果

### 正面

- 可以复用现有开源 MCP 工具接入更多旅行信息渠道，不需要每个来源都加进 Tripwise 内置工具注册表。
- 用户需要手动指定代码、明确打开服务并逐项批准工具；默认旅行规划流程仍只使用内置工具。
- 凭证与普通旅行 JSON 分开；一个 MCP 服务失败不会使天气、网页搜索或行程提案整体失败。
- 失败工具的安全重试参数随来源保存在本机旅行数据中，并进入用户主动导出的旅行备份；参数可能含必要旅行查询文本，备份前用户应检查内容。

### 代价与已知限制

- 同一 MCP 服务连接要在每轮规划时启动，增加请求延迟；新协议探测会增加一次请求，stdio 会短暂启动一个探测子进程；最多 8 个服务并行连接以控制时间。
- MCP 工具注释只是服务自述。即使被选中的工具标为只读，恶意服务仍可能修改文件、联网或读取用户权限可访问的数据。
- 命令和参数明文存本地设置，用户需避免在参数中粘贴凭证。环境密钥可以被接收它的服务读取；简单回显脱敏不等于泄露防护。
- 目前没有后台主动探测、后台任务恢复、远程 MCP OAuth、WebSocket transport、进程级资源限制、自动工具权限审核或第三方兼容性认证；SSE 仅为迁移兼容，供应商优先使用 Streamable HTTP。设置页的最近调用状态不是持续健康检查。
- 小红书等平台的 MCP 适配器仍需单独评估平台规则、登录态授权、隐私和维护风险。接入 MCP 不会自动解决抓取许可或数据真实性问题。

## 替代方案

### 仅使用内置连接器

安全面更简单，但渠道接入必须随 Tripwise 发版，无法利用用户已部署的开源工具；不满足进阶用户扩展渠道的产品目标。

### 为每家供应商单独编写内置连接器

固定核心服务使用内置连接器时能获得更稳定的结构化结果；但长尾渠道都要 Tripwise 单独开发和维护，无法满足用户通过 MCP 扩展来源的需求。

### 在应用内持久运行 MCP 服务

减少每轮启动延迟，但会增加进程健康管理、崩溃恢复、设置变更和应用退出清理复杂度；首版采用单轮连接生命周期。

### 依靠工具注释自动放行

容易上手，但把权限决定交给外部服务自我声明；不采用，所有可用工具仍需用户明确勾选。

## 验证与人工审阅

- 自动测试使用确定性 stdio、旧/新协议 Streamable HTTP 和 SSE fixture，覆盖新协议探测及旧协议回退、认证注入、同源限制、草稿预检、不落盘配置、工具白名单、高德个人地图动作拦截、来源格式、只读工具来源重试、参数凭证过滤、凭证直接回显脱敏和连接关闭；持久化测试覆盖重启、备份往返和凭证字段拒绝。
- 仍待验证：目标用户是否理解本机命令权限、远程服务数据去向和旅行参数留存；高德 MCP 是否可用用户 Key 稳定连接及其来源字段；Agent-Reach 自带 MCP 当前仅暴露状态查询，不能视为社媒搜索连接器；Windows/Linux 运行权限与退出清理；恶意服务演练和真实数据最小化。
- 关闭标准：完成可用性审阅、目标平台检查和第三方来源规则审查；安全风险被清楚记录并由产品负责人决定是否接受。当前不宣称这些门槛已关闭。
