# ADR-0010：地图与路线服务商保持一致

| 项 | 内容 |
|---|---|
| 状态 | 已采纳高德地图产品族（用户 2026-10-18 确认）；具体使用许可和数据流未确认，阻止正式发行 |
| 复核日期 | 2026-11-05 |
| 关联 | [PRD](../../PRD.md)、[TECH](../TECH.md)、[ADR-0002](0002-tool-connectors.md)、PR-02、PR-06、PR-08、PR-10 |

## 决策

Tripwise 使用高德 JS API 2.0 底图和高德 Web 服务地点、地理编码及路线能力。不混用 OSM/Nominatim，不把高德坐标绘制到其他地图底图。用户确认的行程可考虑再交接到高德专属旅行地图；该外部写入流程尚未实现，必须由用户预览并再次确认。

内置连接器负责可校验的 POI 与路线数据。官方远程 MCP 可作为用户逐项批准的信息渠道；自由文本结果不能绑定精确路线指标。生成专属地图、导航、打车、订票等外部写入或交易动作不交给 Agent 自动执行。

## 当前数据流

| 环节 | 当前实现 |
|---|---|
| 查询与模型 | 模型按需调用 `estimate_route`；结构化路线选项和摘要返回模型。连接器记录脱敏调用结果与端点解析状态，不记录地点或请求参数。见 [`routes.ts`](../../../src/main/connectors/routes.ts)。 |
| 行程绑定 | 行程提案只把本轮唯一匹配的成功路线来源绑定到同日相邻停靠点，并校验端点、方式和日期；未匹配来源以包含查询信息和行动提示的 `route_source_not_bound` warning 返回模型，由模型决定修订、必要重查或忽略，不自动重查。见 [`itinerary.ts`](../../../src/main/connectors/itinerary.ts)。 |
| 备份与导出 | 旅行 JSON 备份包含路线估算和地点坐标；Markdown 行程会输出路线说明与估算。见 [`backups.ts`](../../../src/main/persistence/backups.ts)、[`itinerary.ts`](../../../src/shared/itinerary.ts)。 |
| 地图脚本 | JS API 2.0 从高德在线加载，不随安装包打包；安全密钥留在主进程代理，renderer 只获得受限地图配置。地点按 GCJ-02 绘制。 |

## 官方条款复核

2026-11-05 复核高德[开放平台服务协议](https://lbs.amap.com/pages/terms/)；页面标注更新时间为 2025-12-03。复核[技术服务许可协议](https://developer.amap.com/pages/authorization/)：

- 服务协议第 3.1 条仅为经个人认证、用于个人研究学习的自然人提供基础服务免费配额；其他个人用途可提交工单办理付费许可。Tripwise 的旅行规划用途不能直接视为研究学习。
- 第 3.2.1–3.2.2 条要求组织将服务用于商业目的，或为第三方开发系统时，相关开发者和运营方事先购买技术服务许可；第 5.1、5.5 条保留审核应用及拒绝申请的权利。开源分发、用户自带 Key 和本机运行是否满足具体许可条件，协议没有针对 Tripwise 作出结论。
- 第 3.4 条明确限制车载场景、模型/算法训练及相关数据集构建；没有明确禁止或授权普通模型推理，不能把推理等同训练，也不能据此推定模型传递获准。
- 第 3.5 条要求按官方文档开放的功能展示服务数据；禁止直接存储、缓存或通过技术手段抓取、使用服务内部数据/图片。若要脱离高德服务使用相关结果，应提交工单评估。第 3.6 条原则上限于开发者自己使用，仅明确为 SDK 产品开放自然人用户经应用使用的例外。
- 第 4.12.2–4.12.4、4.12.7–4.12.8 条另限制复制交互数据、抓取、脱离服务展示、制作衍生内容和下载/获取服务数据。它们与路线信息进入模型、成为可编辑计划、保存在备份或导出文件的组合方式有关；协议没有明确判定 Tripwise 这种数据流，需书面答复。
- 技术服务许可协议第 10 条进一步限定许可仅用于高德审核确认的场景，许可本身不自动覆盖模型/算法训练及数据集构建；其他服务也不因购买基础许可而自动包含。
- [JS API 2.0 加载说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/load)要求在线加载，不得本地转存或与应用代码混合打包。

**代码证据：**`estimate_route` 将结构化路线响应返回模型；提案连接器按本轮来源进行精确匹配，未关联时回传查询端点、方式、日期、原因及下一步选择，模型决定是否继续查询或修改。路线工具说明要求日程调整后不沿用失配路线。已绑定的路线来源、估时和地点坐标可进入旅行数据、备份和 Markdown。分别见 [`routes.ts`](../../../src/main/connectors/routes.ts)、[`itinerary.ts`](../../../src/main/connectors/itinerary.ts)、[`agent.ts`](../../../src/main/agent.ts)、[`persistence.ts`](../../../src/main/persistence.ts)、[`itinerary export`](../../../src/shared/itinerary.ts)。

**判断：**现行公开条款不能证明该数据流已获授权。路线进入模型是否构成获准的“展示”或服务外使用、用户保存/导出范围，以及单人桌面应用的 Key 和许可主体均属待确认事项。保持高德方案是已采纳的产品选择，不代表许可已通过；本 ADR 是产品发布门禁记录，不构成法律意见。

## 发布门槛

正式发行前取得高德针对 Tripwise 具体实现的书面答复，覆盖：

1. 个人旅行桌面 Agent、开源/安装包分发、开发者认证、每个用户自备 Key 及个人非研究用途的许可要求。
2. POI/路线字段传给用户选择的云模型，用于生成和修改旅行计划是否属于许可范围；需区分普通推理与训练。
3. 采纳的地点/坐标、路线估算和来源能否在本机计划、备份、Markdown 中持久化/导出，以及保留期限和字段限制。
4. 地图页面、结果归属、审图号、链接和专属地图交接要求，以及许可主体、地域、期限、配额和费用。

未获书面确认前，高德集成只按开发预览管理，不宣称条款审查通过。北京测试使用本地结构 mock 时只能验证解析和交互，不代表真实路线。若高德不批准，应按书面回复调整展示/数据流，或暂停相关地图能力并重新评估供应商；仅关闭持久化不足以证明其他使用方式获准。当前没有代用户向高德发工单或购买许可。

## 实现约束

- Web 服务 Key 留在主进程；JS API Key 通过受信任 IPC 提供给地图沙箱；JS 安全密钥留在主进程代理。
- JS 安全密钥不得进入 renderer、旅行数据、备份、日志或模型上下文。用户更换 JS Key 后重启应用。
- 旧 WGS-84 坐标不绘制在高德底图，也不用于高德附近检索；用户通过地图重新定位后才采用 GCJ-02 候选。
- 高德失败时保留地点列表并提示重试，不静默切换地图供应商。所有路线估算都标注查询来源和需出行当天复核。

## 备选方案

- **OpenStreetMap 产品族：**未选择；与用户确认的中国境内高德方案不同，且地点/公共交通覆盖和商用条件需单独评估。
- **暂停高德地图：**若许可不通过，保留地点文字与外部地图链接，关闭高德底图、POI 和路线能力，待评估合规替代方案。
- **高德专属旅行地图：**官方 MCP 提供路线、地点、天气与专属地图能力，产品增量是把已确认计划交给高德 App 行中使用；当前只有产品方向，具体工具 schema、链接留存和 Tripwise 数据流许可仍待确认。详见[官方 MCP 概述](https://lbs.amap.com/api/mcp-server/summary)和[旅行规划案例](https://lbs.amap.com/api/mcp-server/application-case/travel-planning-case)。

## 验收条件

1. 地图、地点和路线只调用高德；地图显示来源归属，Key 与安全密钥遵守上述边界。
2. 旧坐标不会误画；地图加载、地点查询、路线失败均可见且可恢复。
3. 取得书面许可并据此调整模型传递、持久化、备份和导出；若未获许可，暂停相应能力并通过回归验证。
4. macOS、Windows、Linux 安装包均完成人工地图验收；未完成的平台不得标记为正式发布。
