# ADR-0008：小红书 OpenCLI 只读连接器

| 项 | 内容 |
|---|---|
| 状态 | 已接受用于默认关闭的实验试点；正式发布门槛待审核 |
| 日期 | 2026-10-17 |
| 关联需求 | PR-02、PR-04、PR-11 |

## 背景

旅行规划需要真实游客的路线、体验和避坑线索。小红书是用户明确提出的重要信息渠道，但其公开授权接口目前没有可依赖的通用笔记搜索与读取能力：授权范围页列出 `basic_info`，`read_notes` 仍处于规划中。直接把页面抓取写进 Tripwise 会让产品承担登录态、DOM 变化和账号数据处理责任。

[OpenCLI 小红书适配器](https://github.com/jackwener/OpenCLI/tree/e6174a952c763a836a9bb0dd2f097d2962b3876b)复用用户自己的 Chrome/Browser Bridge，暴露搜索与笔记读取命令。它依赖站点页面结构，并有公开的验证码、登录墙和筛选布局故障报告，因此只能作为可选实验连接器，不能视作官方 API 或稳定数据服务。[官方授权范围](https://openaccount.xiaohongshu.com/docs/scope)、[官方 API 参考](https://openaccount.xiaohongshu.com/docs/api-reference)。

2026-09-24 复核时，OpenCLI 最新发布为 2.0.2（2026-10-20）；其当前文档仍提供 `xiaohongshu search` 和 `xiaohongshu note`，同时也包含通用浏览器、下载与账号写入能力。Tripwise 仅调用这两个固定只读命令，但本机未安装该程序，2.0.2 尚未做真实联测；官方小红书授权目录仍只列 `basic_info` 已开放，`read_notes` 处于规划中。[OpenCLI 2.0.2 发布记录](https://github.com/jackwener/OpenCLI/releases/tag/v2.0.2)、[当前小红书适配器文档](https://github.com/jackwener/OpenCLI/blob/main/docs/adapters/browser/xiaohongshu.md)、[官方授权范围](https://openaccount.xiaohongshu.com/docs/scope)。

## 决策

以 OpenCLI CLI 作为独立、用户自行安装的只读适配器，由 Electron 主进程调用。连接器默认关闭；用户必须选定绝对程序路径并显式启用。Tripwise 只调用固定的 `xiaohongshu search` 和 `xiaohongshu note` 参数，不把模型内容拼接为 shell 命令，也不开放通用浏览器、`ask`、评论、下载、收藏或写入命令。2.x 兼容性须在受支持设备上用真实二进制联测后才能标为可用。

搜索每次最多返回 5 篇笔记，站点操作通过串行队列并至少间隔 3 秒。笔记读取只能针对本旅行已经保存的小红书搜索来源，不能传入任意站点链接。来源卡和模型上下文将这些内容标记为社区经验，不允许作为开放时间、价格、交通等官方事实的唯一依据。

OpenCLI 命令执行使用绝对路径、`shell: false`、最小环境变量、忽略 stderr、90 秒超时和 2 MB stdout 限制。连接器只规范化标题、页面作者、互动数、链接、正文和标签等白名单字段。错误信息经映射后展示，不把 CLI 原始 stderr 交给模型。

## 边界与数据处理

- Tripwise 不安装或更新 OpenCLI/Browser Bridge，不读取、复制或注入 Chrome Cookie，不自动登录，不绕过验证码、访问控制或反爬限制，不读取评论、收藏、通知、个人主页，不下载媒体，也不进行任何社媒写入。
- 本机命令以当前用户权限运行，Tripwise 没有 OS 级进程沙箱。用户必须信任自己配置的程序及其依赖；路径选择和固定参数只能限制 Tripwise 的调用形态，不能证明该程序本身安全。
- 搜索词会交给 OpenCLI 并由其通过用户控制的 Chrome 访问小红书。平台返回的完整链接可能含 `xsec_token`；该链接会保存在本机来源记录，并随用户主动导出的旅行 JSON 备份一起导出。它不是登录凭证，但仍按可识别访问参数处理。
- 模型上下文中的链接会剔除 `xsec_token`；研究浏览器使用短期快照编号跟进笔记，实际链接只保存在主进程内存和本机来源记录中。其他站点的敏感查询参数不随快照链接加载。
- OpenCLI、Browser Bridge 和小红书页面返回的文本均为不可信输入。来源页面内容不可覆盖系统指令，也不可授权额外工具调用。
- 登录墙、验证码、权限不足、超时、空结果或 DOM 变化出现时停止当前操作，保留可理解的失败状态。用户可以改用普通网页面板、粘贴链接/正文或手动导入，不静默切换认证会话。

## 后果

### 正面

- 能在保留用户现有 Chrome 登录态的前提下接入用户关注的攻略渠道，不要求 Tripwise 保存社交账号凭证。
- OpenCLI 的站点适配与旅行规划分层；未来可替换适配器，主应用仍消费统一来源记录。
- 默认关闭和来源级失败回退保留了用户选择；普通网页、粘贴和导入路径不依赖该连接器。

### 代价与风险

- Chrome/Browser Bridge 的安装、配对和登录需要用户自行维护；本轮只覆盖调用边界的模拟测试，没有真实账号或多平台运行证据。
- 页面 DOM 与平台限制可随时变化，搜索可能为空、遇到验证码或失效；最多 5 条和 3 秒间隔是产品限额，不构成平台许可或成功率保证。
- 连接器会启动一个由用户配置的本机可执行程序，且无操作系统沙箱。设置说明、绝对路径校验、固定子命令和数据去向提示不能替代对 OpenCLI 代码及用户系统的独立安全审查。
- 来源链接可能携带 `xsec_token`，旅行备份也会包含该链接。用户应按个人资料链接保护备份。

## 发布门槛

该方案只批准实验性实现，不等于批准正式启用或公开发布。默认关闭状态应持续到以下条件完成人工审阅：

1. 针对实际分发形态和目标市场完成平台条款、法律与隐私审查，并记录依据及责任人。
2. 在受支持的目标系统上完成用户自备 OpenCLI/Browser Bridge 的真实会话安装与读操作验证，包含登录墙/验证码/断连的可见失败和手动回退。
3. 明确告知查询词、来源链接、正文以及备份的本地和外部去向，并审阅本机进程权限及撤销/删除体验。
4. 目标用户试点表明连接器安装和失败恢复足够易用；若不满足，保留链接与正文导入能力并关闭结构化接入。

## 考虑过的方案

| 方案 | 决定 |
|---|---|
| 将 DOM 抓取直接写入 Tripwise 内置网页面板 | 不采用。将登录态、站点脚本和页面维护耦合到主应用，扩大凭证和维护责任。 |
| 依赖官方开放 API | 暂不可行。当前公开目录没有通用笔记搜索/读取接口。 |
| 通过 Agent-Reach MCP 直接检索小红书 | 不采用为本连接器后端。研究的固定版本 MCP 只注册 `get_status`；内容检索需其 Skill 再调用 OpenCLI 等工具。 |
| 用户提供链接或粘贴攻略正文 | 作为稳定回退持续支持；不满足用户提出的渠道主动搜索需求，因此保留默认关闭的可选试点。 |
