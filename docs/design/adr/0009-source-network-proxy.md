# ADR-0009：旅行资料连接器网络代理

| 项 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-10-18 |
| 关联需求 | PR-02、PR-03、PR-11 |

## 背景

旅行资料服务需要访问公开搜索、天气、地点和路线接口。一次实际环境验证中，DuckDuckGo 与 Nominatim 的直连请求超时；经用户配置的本机 HTTP 代理请求，两者均返回 HTTP 200。此前连接器使用 Node `fetch`，它没有使用 Git 专属代理配置，也不会自动继承所有桌面系统代理设置。

Electron 官方文档说明，主进程 `net.fetch` 使用 Chromium 网络栈并转交给默认 Session；`session.setProxy` 可为 Session 配置固定代理或恢复系统代理设置。[Electron `net` API](https://www.electronjs.org/docs/latest/api/net)、[Electron `session` API](https://www.electronjs.org/docs/latest/api/session)、[ProxyConfig](https://www.electronjs.org/docs/latest/api/structures/proxy-config)。

## 决策

- 网页搜索、天气、地点和路线连接器使用 Electron `net.fetch`；通过默认 Session 的代理配置访问公开服务。
- 设置页提供可选“旅行资料网络代理”地址，支持无认证 HTTP、HTTPS 和 SOCKS5 地址。空值显式使用操作系统代理设置。
- 来源代理只配置在默认 Session。隔离研究网页由独立 Session 访问本机随机端口的出口保护器；保护器向默认 Session 查询系统或用户代理路由，再把每个目标固定到已校验的公网 IP，避免研究网页绕过目标校验或形成本机代理循环。详细安全决策与验证范围见 [ADR-0015](0015-research-egress-guard.md)。
- 来源代理不用于模型 API。模型请求继续使用独立 Node `fetch`，避免把模型密钥转发给资料代理。
- 代理地址仅保存协议、主机与端口；拒绝账号、密码、路径、查询参数和片段。用户需要带认证的代理时，应先在本机建立受信任的本地转发代理。
- 保存代理地址会即时应用到 Session；若设置写盘失败则尽力恢复此前配置。代理不可达时由对应连接器的现有错误状态显示，用户可以单独清空代理并重试。

## 考虑过的方案

| 方案 | 决定 |
|---|---|
| 继续使用 Node `fetch` 并依赖环境变量 | 不采用。GUI 启动时环境变量可能不存在；本次失败环境也未设置代理变量。 |
| 所有请求统一使用全局 Node 代理代理器 | 不采用。会把模型 API 一并路由，可能将模型密钥暴露给新增的代理运营方；也需要额外依赖。 |
| 仅使用系统代理 | 不采用。无法覆盖只在本机运行、尚未设为系统代理的服务。 |
| 让用户按需填写旅行资料代理，并使用 Chromium Session | 采用。直接满足本次实测问题，沿用 Electron 的网络栈和代理配置。隔离研究网页另经受限本机转发器，以固定目标地址。 |

## 风险与边界

- 用户必须信任自己配置的代理。代理运营方可以观察目标站点；若代理进行 HTTPS 解密，也可能读取请求内容。设置说明明确这一点。
- 默认空值采用系统代理，不会暗中使用特定用户的本机端口。代理 URL 不支持账号密码，也不以 API Key 形式存储凭证。
- 第三方 MCP 与 OpenCLI 由它们自己的传输实现负责，不由此设置接管。
- 代理配置保存成功不代表代理服务可连通；服务不可用时保留逐来源失败与重试行为，不阻塞应用启动。研究网页保护器无法启动时，网页研究入口保持关闭。

## 验收

- 旧 schema v7 数据启动后自动迁移到 v8，保留旅行和设置，并将来源代理设为空。
- 代理地址校验覆盖合法协议、规范化、认证信息、路径和无效地址。
- HTTP 连接器使用 Electron 注入的传输；Node 单元测试仍可替换 `fetch`。
- 实际代理可达性只用不含凭证的公共查询验证；模型 API 请求不走该来源代理。
- Chromium 研究网页的实际代理连接和已校验 IP 转发由 [ADR-0015](0015-research-egress-guard.md) 的请求级验收覆盖。
