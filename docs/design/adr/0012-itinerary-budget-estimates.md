# ADR-0012：行程预算采用分项估算与确定性汇总

| 项 | 内容 |
|---|---|
| 状态 | 已采纳，适用于中国境内首发 |
| 日期 | 2026-10-19 |
| 关联 | [PRD PR-05](../../PRD.md)、[TECH](../TECH.md#1-当前实现)、[schema v15 与备份 v11](../TECH.md#1-当前实现) |

## 背景

个人旅行预算横跨航班、城际交通、住宿、市内交通、门票、餐饮和其他支出。只生成一个总数无法告诉用户依据、人数/晚数等数量假设，也容易把模型算术错误或未知费用隐藏起来。预算还需要跟随候选行程、版本、来源移除、手动编辑和备份保持一致。

## 决策

- 预算估算附加到每个 `ItineraryOption`，只在用户填写预算偏好或提出费用问题时要求模型返回。
- 首发仅支持人民币 CNY，金额以整数分保存；模型逐项提交费用类别、单价区间、数量、单位、依据、证据等级和来源 ID。应用负责乘数量并汇总区间，不让模型自行计算最终合计。
- 旅行简报存在预算偏好或当前话题最近提出费用估算时，规划候选必须包含预算。用户在当前话题明确取消后不再强制预算；之后重新询问费用可恢复要求。
- 七类费用必须逐类有费用项或有理由的不适用声明。适用但金额未知的项目标为待核验，金额为空；未知类别不按零元处理。只要存在待核验、缺失类别或来源需复核，界面和导出就显示已计入项目小计。
- `sourced` 项只能引用当前旅行中的成功来源；`estimated` 项需写明估算依据；`pending` 项不能带金额或来源。应用检查来源 ID 和状态，但不声称已语义核实来源正文是否支持金额。
- 手动编辑行程后清除预算，防止新计划沿用旧估算。移除某个有来源费用项的最后一条来源时，将金额清空并降为待核验；估算项保留数字并提示复核。
- 预算随候选、确认行程、Markdown 和旅行 JSON 备份保存。持久化 schema 升为 v15，旅行备份升为 v11；旧数据不补造预算。

## 备选方案

- **让模型直接返回全程总价：** 实现更少，但不能审阅项目依据、数量和缺项，也容易出现无法解释的总额；不采用。
- **首版接入航班/酒店交易 API：** 可能得到更实时的报价，但依赖区域、账户、日期和供应商覆盖，并会把规划工具推向预订产品；首发不采用。未来若接入，只把服务返回的报价作为独立来源项。
- **自动把缺失类别按零计算：** 结果更像完整总额，但会造成错误的预算预期；不采用。

## 结果与复审条件

用户可以看到每项价格范围、数量、依据、来源和未计入类别，并在逐轮修订中检查预算项目变化。代价是部分估算可能只能显示小计；来源状态不保证金额适用当前日期、人数或客票条件；自由文本预算偏好暂不自动转换为预算上限或判断超支。若支持多币种、实际供应商报价或预订能力，应重新评估数据模型、汇率时点和报价有效期。

## 验证

`tests/budget-estimate.test.ts` 覆盖整数分汇总、数量乘法、未知类别、来源状态、工具入口校验、预算卡片、候选对照、修改差异和 Markdown 导出；`tests/source-removal.test.ts` 覆盖删除来源后的预算降级；`tests/trip-brief.test.ts` 覆盖 v14→v15 迁移与 v10 备份校验。2026-10-19 完整候选包流程通过 TypeScript、399 项 Vitest、19 项脚本测试、开发版与 macOS 候选版 E2E，以及 macOS/Windows/Linux 候选产物检查。真实模型对预算质量的评估仍待完成。
