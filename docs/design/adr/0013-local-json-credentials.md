# ADR-0013：使用应用目录中的本地 JSON 保存服务凭证

## 背景

Electron `safeStorage` 在 macOS 上依赖 Keychain。当前 ad-hoc 桌面构建反复触发系统授权窗口，使用户难以判断应用何时读取凭证，也让首次使用和自动化验收受系统交互阻塞。Windows、Linux 和 macOS 的凭证库行为也不一致。

Tripwise 是单用户桌面应用，当前没有云同步或团队共享需求。需要一种各桌面平台行为一致、启动时不弹系统授权、且便于用户自行检查和修复的存储方式。

## 决策

1. 模型、高德、搜索和 MCP 环境密钥统一保存在 Electron `userData` 目录下的 `tripwise-credentials.json`。
2. 文件采用 schemaVersion 1 的 JSON 格式；主进程校验格式、凭证名、大小和条目数量。未知字段或无效结构会阻止凭证读写并保留原文件，不自动重置。
3. 写入通过临时文件和原子替换完成。POSIX 系统将凭证文件权限设为当前账户读写（0600）；Windows 依赖当前用户配置目录 ACL，不声称文件内容加密。
4. 应用启动、状态展示、保存普通设置和测试未配置的连接器都不访问操作系统凭证库，也不弹出 Keychain 授权。
5. renderer 只接收已保存状态、修复状态和文件路径。凭证值仅由主进程读取，并按连接器需要传给对应服务或 MCP 子进程。
6. 连接设置明确说明文件未加密、同一账户的其他程序可能读取。用户可从设置页打开文件或在编辑后重新载入。
7. 旧版 `tripwise-secrets.json` 不自动解密、迁移或删除；用户需在新设置页重新录入要继续使用的密钥。确认旧 Key 已轮换或弃用后，用户可自行删除该文件及只供旧版 Tripwise 使用的钥匙串记录。

## 理由

- 所有桌面平台使用同一份应用逻辑，不需要每个平台维护不同的钥匙串授权和恢复状态。
- 启动和读取凭证不需要系统弹窗，减少首次配置、桌面使用和自动化验收中的中断。
- 用户可以检查和修复配置文件；格式损坏时保留原文件，不以空配置覆盖。
- 旅行资料和凭证仍分开存放；旅行备份、Markdown 导出和模型上下文不包含凭证文件。

## 代价与限制

- JSON 内容是明文。同一 macOS、Windows 或 Linux 用户账户下运行的其他程序可能读取它；文件权限不是加密边界。
- 当前不支持凭证云同步、多用户隔离、密码加密或自动迁移旧密文。用户应只在受信任的账户中使用该应用，并自行管理旧文件。
- Tripwise 不访问或批量修改操作系统凭证库。清理旧版 Tripwise 存储时只允许针对已核验的专属服务名和账户名操作，不删除其他应用或共享条目。

## 验收

- 启动应用及查看连接状态不访问 Electron `safeStorage`，不调用 `security` 命令，也不请求系统凭证授权。
- 保存、读取、清除和 MCP 凭证事务通过单元测试；POSIX 文件权限、原子写入、损坏文件保留与状态脱敏均有覆盖。
- 设置页明确披露明文风险、旧文件不迁移和修复入口。
- 构建产物禁用 Electron Cookie 加密 fuse，避免其独立触发 macOS Keychain 访问。
